# Threat Model (draft)

> First draft, written in Phase 0. Review it at the end of each phase and whenever an integration is added.

## What we protect

| Asset                                                      | Why it matters                                                    |
| ---------------------------------------------------------- | ----------------------------------------------------------------- |
| GitHub App private key and webhook secret                  | Lets an attacker read repositories or forge events                |
| Azure identity (service principal or federated credential) | Read access to cloud resource metadata                            |
| Migration-check database credentials                       | Access to a user's application database                           |
| User sessions                                              | Access to all connected project data                              |
| Stored evidence and findings                               | May contain commit messages, URLs, resource IDs, and log excerpts |

## Trust boundaries

1. Internet → API (webhooks, browser requests)
2. API and worker → external providers (GitHub, Azure, health endpoints, application databases)
3. Worker → user-configured URLs (health checks): the main SSRF surface
4. ReleaseLens → outbound channels (email): the main data-leakage surface

## Threats and mitigations

| #   | Threat                                                    | Mitigation                                                                                                                                                                            | Verified by                                                                                                                                            |
| --- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T1  | Forged or replayed webhooks                               | HMAC-SHA256 over the raw body with constant-time comparison; unique delivery IDs; payload size limits                                                                                 | Unit tests for signature checks; API tests for wrong/tampered signatures and redelivery; worker tests for idempotent processing (scenario 7) (Phase 3) |
| T2  | SSRF via health-check URLs                                | http/https only; resolve DNS and block loopback, private, link-local, and cloud metadata ranges (e.g. 169.254.169.254); revalidate every redirect; bounded timeouts and response size | Tests with blocked targets and redirect chains                                                                                                         |
| T3  | Secrets leaking into logs, findings, reports, or emails   | One shared redaction utility (tokens, passwords, connection strings, auth headers, common secret patterns) used by the logger and every output; store bounded excerpts only           | `packages/redact` tests (scenario 8); applied to API logs and audit metadata (Phase 2)                                                                 |
| T4  | Cross-project data access                                 | Server-side organization/project check on every request; never trust client-supplied IDs alone                                                                                        | API integration tests: cross-org access returns 404 on every project route (Phase 2)                                                                   |
| T5  | Credential theft from the database                        | Credentials encrypted at rest (managed key service when deployed); never sent to the browser; revoking an integration deletes them                                                    | Revocation integration tests                                                                                                                           |
| T6  | Over-privileged integrations                              | GitHub App with read-only permissions; Azure `Reader` scoped to one resource group; migration DB role with SELECT on `_prisma_migrations` only                                        | GitHub App permissions documented in docs/github-app.md: Actions, Contents, Deployments, Metadata, all read-only (Phase 3)                             |
| T7  | ReleaseLens modifying user infrastructure                 | No write APIs called; the migration inspector runs one fixed query; no arbitrary SQL or shell commands                                                                                | Code review rule and tests                                                                                                                             |
| T8  | Misleading diagnosis (stale data shown as healthy)        | Data freshness tracked per integration; stale or missing data produces `unknown`                                                                                                      | Missing- and stale-data rule tests                                                                                                                     |
| T9  | Denial of service (webhook floods, slow providers)        | Rate limits, payload limits, queue concurrency limits, timeouts, retries with backoff and jitter                                                                                      | Webhook body limit (5 MB, tested), queue concurrency limit, request timeouts, backoff with jitter honouring GitHub rate limits (tested)                |
| T10 | Supply-chain compromise                                   | Committed lockfile, Dependabot, CI with a read-only token, versioned actions                                                                                                          | CI configuration                                                                                                                                       |
| T11 | Sensitive data sent to an AI provider (if ever added)     | Off by default; only redacted evidence is sent; a deterministic path always exists                                                                                                    | Deferred until AI summaries are considered                                                                                                             |
| T12 | Session theft or fixation                                 | Random 256-bit tokens, only SHA-256 hashes stored; `HttpOnly`, `SameSite=Lax`, `Secure` on HTTPS; expiry and logout delete sessions                                                   | API integration tests (expired, forged, logged-out sessions)                                                                                           |
| T13 | CSRF on cookie-authenticated requests                     | `SameSite=Lax` plus a global guard requiring the dashboard `Origin` on every non-GET request                                                                                          | API unit and integration tests                                                                                                                         |
| T14 | OAuth login CSRF or code interception                     | `state` bound to a short-lived cookie, PKCE (S256), exact redirect URI; GitHub token discarded after reading the profile                                                              | API integration tests with a fake GitHub                                                                                                               |
| T15 | Script injection in the dashboard                         | React escaping; no `dangerouslySetInnerHTML`; frame, sniffing, and referrer headers. **Open:** no Content Security Policy yet                                                         | Manual review; CSP planned                                                                                                                             |
| T16 | An organization connecting another account's repositories | The API asks GitHub whether the installation can access the repository; an installation linked to one organization cannot be used by another (409) and is hidden from it              | API integration tests (Phase 3)                                                                                                                        |
| T17 | Out-of-order or replayed events corrupting state          | Upserts keyed by GitHub run ID, applied only when GitHub's `updated_at` is newer; delivery IDs unique                                                                                 | Worker integration tests (Phase 3)                                                                                                                     |
| T18 | Webhook payloads retaining sensitive data                 | Payload cleared once processed; delivery records deleted after 30 days; GitHub App private key read from a file outside the repository (`*.pem` git-ignored)                          | Worker tests for clearing and retention                                                                                                                |

## Open questions
